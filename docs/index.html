Prefers Checker

Your users tell their devices how they need the web to behave: less motion, dark or light, more contrast, less transparency, less data. This extension tests whether the page you are on actually listens, all five at once.

What it checks

Click the toolbar button on any page. You get one row per preference, with a verdict and the evidence behind it:

prefers-reduced-motion

Counts animations actually running on the page, looks for reduced-motion rules in the CSS, and in the deep test checks whether the animations stop when reduction is requested.

prefers-color-scheme

Looks for dark-scheme support in the CSS and meta tags, and in the deep test flips the scheme and measures whether the page's colors actually change.

prefers-contrast

Samples real text on the page and computes WCAG contrast ratios against the effective background, naming the worst offender. The deep test re-samples under a more-contrast request.

prefers-reduced-transparency

Counts frosted-glass surfaces (backdrop-filter and translucent layers) and checks for handling rules. If your browser cannot emulate the setting yet, the row honestly says Not testable instead of failing the site.

prefers-reduced-data

Weighs what the page actually downloaded, counts images and videos, flags autoplay, and looks for data-saver handling rules.

How it works

Instant scan. The moment you open the popup, the extension probes the live page: its stylesheets, its running animations, its text contrast, its resource weight. No special access, no waiting.

Deep test. One button press attaches Chrome's debugger protocol to the tab and flips each media feature to the state the user is asking for, using Emulation.setEmulatedMedia, the same mechanism as DevTools' Rendering panel. It re-measures in every state, then clears the emulation and lets go. This is the part a website cannot do: a page in an iframe can never force these settings on someone else's site, but an extension with the debugger permission can.

Verdicts are Pass, Partial, Fail, Unknown, or Not testable, each with the measured evidence one click away. No score is invented: if the tool could not measure something, it says so.

Install

Prefers Checker is not on the Chrome Web Store yet, so it installs the developer way:

  1. Download the zip above and unzip it.
  2. Open chrome://extensions in Chrome.
  3. Turn on Developer mode (top right).
  4. Click Load unpacked and select the unzipped folder (the one containing manifest.json).

Pin it to the toolbar, open any page, and click it. Close DevTools on the tab first if you plan to run the deep test; the two cannot attach at once.

Honest limits

  • Cross-origin stylesheets are partly invisible to any extension, so rule detection can miss handling that lives in a CDN stylesheet. The report tells you how many sheets it could not read.
  • Contrast sampling is a heuristic. Text over photos and gradients is counted as unmeasurable, not guessed at.
  • Page weight counts resources loaded so far. A page that lazy-loads more later weighs more than the scan shows.
  • Support for emulating reduced-data and reduced-transparency varies by Chrome version. When the browser refuses to flip one, the verdict rests on the instant evidence and says so.

Open source, contributions welcome

Prefers Checker is MIT-licensed and developed in the open at github.com/SydBal/prefers-browser-extension. The analysis core is deliberately boring: plain JavaScript, no build step, no dependencies, and the scoring logic is DOM-free with a node test suite, so most of it can be hacked on without loading the extension at all.

Good ways in: try it on sites you build and file issues with the reports you get, suggest verdict rules for cases the tool gets wrong, or pick up a starter issue. Read the README in the repo for the layout and the known-limitations list before a pull request, so we are arguing about the same facts.
